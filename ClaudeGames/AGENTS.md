## Кто ты и что это за проект

Ты — агент, продолжающий готовый проект **ClaudeGames**: игровая платформа —
**Telegram Mini App со 106 браузерными мини-играми** + Node.js-сервер +
Telegram-бот + админ-панель (управление играми, статистика, бот, баннерная
реклама, Google AdSense).

**Целевая аудитория:** люди из небогатых стран со слабыми телефонами и
медленным интернетом. Отсюда все технические решения: никаких фронтенд-
фреймворков, ноль внешних ассетов (вся графика рисуется кодом/эмодзи),
ленивая загрузка игр по одной, офлайн через service worker, детект слабых
устройств.

**Проект уже написан и проверен.** 106 игр реализованы, каждая прошла
`node --check` и Playwright-смоук-тест в Chromium (последний прогон —
**106/106 passed**). Сервер, API, админка и demo-режим проверены. Тебе НЕ нужно
писать игры с нуля — тебе нужно то, что скажет владелец (скорее всего —
**разместить проект на сервере**; см. раздел «Твоя задача»).

## Как запустить и проверить локально

```bash
# из папки ClaudeGames
npm install            # поставит express + better-sqlite3 (нативный модуль — соберётся сам)
cp .env.example .env   # можно не редактировать — работает и без токена (demo-режим)
npm start              # поднимет сервер на порту 3000
```

- Приложение: `http://localhost:3000/`
- Админка: `http://localhost:3000/admin/` (пароль по умолчанию `admin` — сменить!)
- Открыть конкретную игру напрямую: `http://localhost:3000/?game=<id>`
  (id берётся из `webapp/games/catalog.json`).

**Быстрая проверка, что всё цело:**
```bash
# синтаксис всех игр
for f in webapp/games/*/game.js; do node --check "$f" || echo "FAIL $f"; done
# API живой (сервер запущен)
curl -s localhost:3000/api/health
```

## ТВОЯ ЗАДАЧА (что почти наверняка попросит владелец)

Владелец сказал: **«я запущу того агента и дам ему инструкции, как разместить
игры на сервере».** То есть основная задача — **деплой на боевой сервер**.
Конкретные данные сервера (хост, домен, доступы, платформу) даст владелец.
Ниже — всё, что тебе нужно знать, чтобы быть готовым.

### Что важно знать про деплой именно этого проекта

1. **Один процесс — всё сразу.** Сервер (`server/index.js`) сам отдаёт
   мини-приложение (`/`), админку (`/admin`) и API (`/api`) на одном порту
   (по умолчанию 3000). Отдельно хостить фронтенд не нужно.
2. **HTTPS ОБЯЗАТЕЛЕН.** Telegram открывает Mini App только по `https://`.
   Нужен домен + TLS. Варианты: Caddy (авто-TLS в 2 строки), nginx + certbot,
   или PaaS с встроенным TLS (Railway/Render/Fly). Проксировать 443 → порт
   приложения.
3. **Node.js >= 18** (используется глобальный `fetch` в боте). На сервере
   `npm install` соберёт `better-sqlite3` — нужны build-tools/python, либо
   встанет prebuilt-бинарник.
4. **SQLite нужен постоянный записываемый диск.** База — файл
   `data/minigames.db` (путь настраивается через `DB_PATH`). На эфемерных
   платформах (контейнеры без диска) — подключить volume, иначе статистика и
   настройки будут теряться при рестарте.
5. **Процесс-менеджер:** pm2 / systemd / встроенный супервизор платформы,
   чтобы сервер поднимался после падения и ребута.
6. **Переменные окружения** (файл `.env`, см. `.env.example`):
   `PORT`, `BOT_TOKEN` (позже), `WEBAPP_URL` (публичный https-URL),
   `ADMIN_PASSWORD` (**обязательно сменить!**), `ADSENSE_CLIENT` (позже),
   `DB_PATH`. Токен бота и AdSense можно вписать позже прямо в админке — они
   хранятся в БД и перекрывают `.env`.

### Порядок деплоя (общая канва — уточни детали у владельца)

1. Доставить код на сервер (`git clone` нужной ветки или загрузка папки).
2. `npm install --omit=dev` (или обычный install).
3. Создать `.env`: задать `PORT`, `ADMIN_PASSWORD`, при наличии — `WEBAPP_URL`.
4. Запустить под pm2/systemd; проверить `curl localhost:$PORT/api/health`.
5. Поднять reverse-proxy с TLS на домен → порт приложения.
6. Открыть `https://<домен>/` (приложение) и `/admin` (сменить пароль!).
7. **Когда будет токен бота:** в админке → «Бот» вписать токен и `WEBAPP_URL`
   (тот же https-домен) → бот стартует сам. У @BotFather: `/newapp`, указать тот
   же URL, чтобы включить Mini App и кнопку меню.
8. **Когда будет AdSense:** в админке → «AdSense» вписать client id и slot-id.

### Проверка после деплоя
- `https://<домен>/` открывает каталог, игры запускаются, счёт сохраняется.
- `https://<домен>/admin` — вход, дашборд, статистика идёт (сыграй пару игр).
- Открытие Mini App внутри Telegram (после привязки токена и URL).

## Правила и ограничения (guardrails)

- **Git:** проект в репозитории `webmysolutions/hitchens`, ветка
  `claude/telegram-minigames-app-uzfypa`, папка `ClaudeGames/`. Разрабатывай в
  этой ветке; коммить осмысленными сообщениями. Контейнеры эфемерны — что не
  закоммичено и не запушено, пропадёт.
- **Не трогай** остальное содержимое репозитория `hitchens` (Jekyll-тема) — оно
  к проекту не относится.
- **Добавляешь игру?** Один файл `webapp/games/<id>/game.js` строго по
  `docs/GAME_API.md` + одна запись в `catalog.json`. При изменении статики
  подними версию кэша: `VERSION` в `webapp/sw.js` и `window.MG_VERSION` в
  `webapp/app.js` (иначе у игроков останется старый кэш).
- **Проверяй перед коммитом:** `node --check` на изменённые игры; если менял
  геймплей — прогони игру в браузере (`?game=<id>`), а не только синтаксис.
- **Секреты не коммить:** реальный `.env` в `.gitignore`. Токен бота, пароль
  админки, AdSense id — только в `.env` на сервере или через админку.
- **Сменить пароль админки** (`admin`) до публичного запуска.
- Не подключай внешние ассеты/CDN/шрифты в играх — это ломает офлайн и грузит
  слабые устройства.
