## 1. ЧТО ЭТО ЗА ПРОЕКТ

**ClaudeGames** — игровая платформа: **Telegram Mini App со 106 браузерными
мини-играми** + Node.js-сервер + Telegram-бот + админ-панель (управление
играми, детальная статистика, бот, баннерная реклама, Google AdSense).

**Целевая аудитория:** люди из небогатых стран со слабыми телефонами и
медленным интернетом. Отсюда решения: без фронтенд-фреймворков, ноль внешних
ассетов (вся графика рисуется кодом/эмодзи), ленивая загрузка игр по одной,
офлайн через service worker, детект слабых устройств, i18n (ru/en).

**Технологии:** ванильный JS на фронте; Node.js ≥18 + Express + better-sqlite3
на сервере; Telegram-бот через raw Bot API (long polling), без SDK.

## 5. ТВОЯ ЗАДАЧА: ДЕПЛОЙ НА СЕРВЕР

Основная задача — **разместить проект на боевом сервере**. Конкретные данные
(хост, домен, доступы, платформу) даст владелец. Что важно именно для этого
проекта:

1. **Один процесс — всё сразу.** `server/index.js` сам отдаёт приложение (`/`),
   админку (`/admin`) и API (`/api`) на одном порту. Отдельный хостинг фронта
   не нужен.
2. **HTTPS обязателен** — Telegram открывает Mini App только по `https://`.
   Нужен домен + TLS (Caddy с авто-TLS / nginx + certbot / PaaS с TLS).
   Проксировать 443 → порт приложения.
3. **Node.js ≥18** (в боте используется глобальный `fetch`).
4. **SQLite нужен постоянный записываемый диск.** База — `data/minigames.db`
   (путь через `DB_PATH`). На эфемерных платформах подключить volume, иначе
   статистика и настройки теряются при рестарте.
5. **Процесс-менеджер:** pm2 / systemd / супервизор платформы (авто-рестарт).
6. **Переменные окружения** (`.env`, см. `.env.example`): `PORT`,
   `ADMIN_PASSWORD` (**сменить!**), `WEBAPP_URL` (публичный https-URL),
   `BOT_TOKEN` и `ADSENSE_CLIENT` (позже — можно вписать прямо в админке, они
   хранятся в БД и перекрывают `.env`), `DB_PATH`.

Канва деплоя (детали уточни у владельца):
1. Доставить код на сервер (`git clone` ветки или загрузка папки).
2. `npm install`.
3. Создать `.env`: `PORT`, `ADMIN_PASSWORD`, при наличии `WEBAPP_URL`.
4. Запустить под pm2/systemd; проверить `curl localhost:$PORT/api/health`.
5. Reverse-proxy с TLS на домен → порт приложения.
6. Открыть `https://<домен>/` и `/admin` (сразу сменить пароль!).
7. Когда будет токен: админка → «Бот» → вписать токен и `WEBAPP_URL` → бот
   стартует сам; у @BotFather `/newapp` с тем же URL (включит Mini App и кнопку).
8. Когда будет AdSense: админка → «AdSense» → client id + slot-id.

Проверка после деплоя: каталог открывается и игры играются по `https://<домен>/`;
`/admin` пускает и показывает статистику (сыграй пару игр); Mini App
открывается внутри Telegram (после привязки токена и URL).

## 7. НЮАНСЫ (полезно знать)

- Флаги-эмодзи в игре `quizflags` не рендерятся на части старых Android — в игре
  есть детект и fallback (буквенный код страны).
- `better-sqlite3` — нативный модуль: на сервере нужен `npm install` (соберётся),
  Node ≥18 обязателен.
- Публичное API: `/api/games`, `/api/config`, `/api/track`, `/api/score`,
  `/api/leaderboard/:game`, `/api/health`. Админ-API под Bearer-токеном после
  `POST /api/admin/login`. Полный список маршрутов и схема БД — в
  `docs/HANDOVER.md`.
- Реклама: свои баннеры (создаются в админке) имеют приоритет; AdSense заполняет
  слот, если баннера под слот нет. Пустые ID ничего не ломают.
